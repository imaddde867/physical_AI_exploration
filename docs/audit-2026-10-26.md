# Independent build-readiness review — 2026-10-26

## Decision

**Proceed as a learning prototype, not as a tested hardware product.** The selected Mac-first architecture is low-cost, local-first, well bounded, and has meaningful reuse paths toward robotics. It is **not yet an AI-powered or physically verified robot**. The first run is a display + sensor-driven embedded system; LLM integration is intentionally later.

## Reproducibility evidence

- **Original repository Python workflow:** green on initial commits; 6 protocol tests. New branch adds 2 host-simulation tests.
- **Independent local checks before PR:** 8 Python unit tests passed, simulated ACK + explicitly labeled synthetic motion event verified.
- **CAD:** OpenSCAD 2021.01 rendered shell and fit-coupon STLs; both individually watertight and single-component. Shell outer extents 90 × 57 × 81 mm; coupon 40 × 40 × 2.8 mm. This verifies geometry construction only, not FDM support strategy or actual PCB fit.
- **Firmware:** compile-and-link test added to CI for native USB and UART variants. No USB device, OLED, sensor or physical multimeter test was possible in this audit.
- **Procurement:** [Otronic ESP32-S3 N16R8](https://www.otronic.nl/en/esp32-s3-n16r8-devboard-16mb-flash-and-8mb-psram), [Otronic OLED](https://www.otronic.nl/en/mini-oled-display-white-0-96-inch-128x64-i2c), [MPU-6050](https://www.otronic.nl/en/acceleration-accelerometer-and-gyroscope-i2c-mpu.html), and [Finland shipping](https://www.otronic.nl/nl/verzending) have official seller pages. Verify actual checkout, boards and headers.
- **Board references:** [Espressif DevKitC-1 pinout](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.0.html), [PlatformIO generic N8 profile](https://docs.platformio.org/en/latest/boards/espressif32/esp32-s3-devkitc-1.html), [Arduino USB CDC behavior](https://docs.espressif.com/projects/arduino-esp32/en/latest/guides/tools_menu.html).

## Go / no-go gates

1. **Procurement:** seller confirms SSD1306 + header population, and board USB port labeling; otherwise pick a verified OLED or different board and update firmware.
2. **Electronics:** power off while wiring; power OLED/sensor from 3V3 and share ground; no motors/batteries.
3. **Firmware:** green build CI; serial ready report; all six ACKs and invalid command rejection on device.
4. **Sensors:** IMU detected at 0x68, triggered reaction and event; record and calibrate threshold, false positives, power behavior.
5. **Mechanical:** print small fit coupon, measure actual PCB, inspect slicer supports, fit-test shell; do not claim finished enclosure beforehand.
6. **AI phase:** add an explicitly permissioned model-to-action gateway, evaluate tool-call reliability and latency before exposing physical actuation.

The 3D-print source is an original *prototype stand*, not a ready-to-use or verified mechanical kit. A later production iteration needs retention clips/screw posts, verified cable management and aesthetic refinement.
