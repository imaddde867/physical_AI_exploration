4. Running MicroPython on the board

MicroPython is a Python interpreter stored in the board's flash. You get a prompt (the REPL) over USB serial and a small filesystem for your files.

Installing it

  1. Hold the BOOT button, plug in USB, release. The board appears as a drive named RPI-RP2.
  2. Copy a .uf2 firmware file onto that drive. The board reboots by itself and the drive disappears.
  3. Open Thonny, choose the MicroPython (Raspberry Pi Pico) interpreter, and you have a REPL.

Steps from firmware/rp2040/README.md; the Waveshare archive includes MicroPython 1.22.2. The BOOT drive is a ROM bootloader, so it works even if your code is broken. That makes it the recovery path.

What runs when

After a reset the interpreter runs boot.py if present, then main.py. Our blink is main.py. Ctrl-C stops a running loop. Ctrl-D is a soft reset: Python objects and most peripheral setup are cleared, the USB connection stays up. A hard reset (power cycle, machine.reset()) resets the hardware too.

MicroPython docs, "Reset and Boot Sequence".

Memory is the constraint

SRAM is 264 kB. The interpreter, heap, and your objects share it. The 134,400-byte framebuffer is one contiguous bytearray, so a fragmented heap can fail an allocation even when total free memory looks sufficient. That is why main.py calls gc.collect() before creating the display and prints gc.mem_free(). The real free figure is unknown until the board runs; record it.

Time in MicroPython

time.ticks_ms() wraps around, so you never subtract it directly. Use time.ticks_diff(now, previous). Our main.py accumulates small differences for this reason, so a blink loop can run for days.
