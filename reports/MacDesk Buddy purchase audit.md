# Choose the screen before buying

*Purchase audit, 2026-10-27*

**Recommendation — hold the order until seller and integration checks are closed.** For your priority—an expressive face beside the MacBook, with occasional short text—the **Waveshare 1.32-inch round AMOLED is the strongest hardware candidate**: the vendor lists 466×466 and 500 cd/m², and Taby supports this board. The 500 cd/m² figure is a specification, not a measured comparison or glare test. Its nominal 1.32-inch diagonal is just 0.04 inch larger than the 1.28-inch GC9A01; the upgrade is primarily pixel density, not a much larger face. Taby is separate firmware; its support does not supply the desired Mac USB bridge, and custom firmware/UI integration is still needed. Taby’s round case is “coming soon.” Confirm stock, checkout total and enclosure path before buying. ([Waveshare 1.32](https://www.waveshare.com/product/esp32-s3-touch-amoled-1.32.htm), [Taby install matrix](https://github.com/TRIIIS-LABS/firmware-taby/blob/main/INSTALL.md), [Taby project](https://github.com/TRIIIS-LABS/firmware-taby))

## The repo proves a face demo, not a Mac companion

The checked-in path sends one allowlisted face command over USB JSONL to an ESP32-S3. Firmware draws one 240×240 image with small mood/blink changes; an optional MPU-6050 can emit shake events. There is **no implemented text, timer, macOS notification ingestion, music, lyrics, screen awareness, agent status, voice, camera, network service, or AI**. Those features would require new Mac-side integrations and a text/event protocol. The README and protocol source support that boundary; describing the current product as a reactive face prototype is accurate. ([README](../README.md), [protocol](../macdesk/protocol.py), [firmware](../firmware/src/main.cpp))

| Capability | Current evidence | Practical status |
|---|---|---|
| Face, moods, blink | Six face names; blink and minor mood overlays | Implemented; hardware output unverified |
| Timers and short text | No timer or text command/rendering path | Proposed; modest host/protocol/UI work |
| App and coding-tool status | No integration in repo | Proposed; Claude Code hooks/statusline can expose configured session data; Codex SDK/app-server serve supported workflows, not arbitrary existing desktop-chat internals. Do not promise desktop token counts. ([Claude statusline](https://code.claude.com/docs/en/statusline), [Codex platform](https://developers.openai.com/blog/codex-as-a-platform)) |
| Notifications | No integration in repo | Own app notifications are supported; no general documented API for reading other apps’ notification bodies. ([Apple UserNotifications](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter)) |
| Music and lyrics | No integration in repo | Track metadata is conditional on app/account authorization; lyrics text access and display rights are not established. ([MusicKit](https://developer.apple.com/documentation/musickit/song), [Spotify playback API](https://developer.spotify.com/documentation/web-api/reference/get-information-about-the-users-current-playback)) |
| Screen awareness | No integration in repo | Possible only with explicit ScreenCaptureKit permission and an image capture path; OCR reads supplied images, not the screen by itself. ([ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos), [Vision OCR](https://developer.apple.com/documentation/vision/recognizing-text-in-images)) |

“Tokens” needs a narrow definition: a supported agent integration might report session/context or cost-related fields, but that is not the same as account-wide subscription quota. Claude Code documents statusline session data; this audit found no supported general attachment to a private, already-running Codex desktop chat. A local hook/USB bridge has no model charge by itself; calling a hosted model does. Do not treat undocumented desktop logs or files as stable APIs. ([Claude statusline](https://code.claude.com/docs/en/statusline), [Codex platform](https://developers.openai.com/blog/codex-as-a-platform))

## The 1.32-inch round board best fits the stated priority

The repo’s Otronic OT8724 listing is €8.99 for a 240×240, 32.4 mm round GC9A01 display, with an 8-pin, 2.54 mm-pitch module. It lists 2.8–3.3 V, but does **not** establish that headers are fitted or how BLK should be driven. “4-wire SPI” describes the bus, not four physical pins. The €40.03 BOM is an advertised-price estimate, not a cart quote; its accessory line prices were not individually rechecked. Finland tracked shipping is listed as €8, but VAT/shipping/stock and final checkout were not verified together. ([Otronic display](https://www.otronic.nl/en/128-rond-tft-lcd-240240-gc9a01-spi-voor-arduino.html), [Otronic shipping](https://www.otronic.nl/nl/verzending), [repo BOM](../docs/bom.md))

The Waveshare board keeps the character form while providing far more pixels, touch, and an ESP32-S3 on one board. With Taby or custom firmware, it is the strongest inference for a polished face and occasional labels, not a proven text-reading experience: font size, glare, viewing distance, case fit and desk usability remain untested. If readable lyrics or persistent snippets become the priority, a small 800×480 HDMI monitor offers more area and direct Mac display operation, but it becomes a separately powered monitor; this audit did not establish its current price or Finland landed cost. ([Waveshare specs](https://www.waveshare.com/product/esp32-s3-touch-amoled-1.32.htm), [HDMI manual](https://files.waveshare.com/upload/4/46/4inch_HDMI_LCD_User_Manual_EN.pdf))

## Build only the smallest useful companion

1. **Choose the display path.** For the stronger face-first experience, confirm 1.32 board revision, stock, total price, round-case plan and firmware path before purchase. For the existing GC9A01 path, get seller confirmation of headers/BLK or choose the documented cabled Waveshare module; verify MCU pin mapping before wiring. Defer the IMU.
2. **Keep the first software local and simple.** Add deterministic timer/manual events and short labels to one Mac host process; leave the ESP32 as renderer. Preserve the expressive face as the default, with brief text only on demand. No camera, IMU, motors, battery, microphone, cloud model or AI subscription is needed initially.
3. **Add integrations one at a time.** Start with opt-in foreground app identity and supported Claude Code hooks or a Buddy-owned Codex workflow. Treat screen capture as a separate user-started permission with pause/stop controls. Use track metadata for music reactions; defer lyrics pending an approved source and terms. Do not ingest arbitrary notification bodies or infer access to account quotas.
4. **Fit and observe before enclosure work.** Test readability, colors, USB reconnect, cable routing and actual board dimensions on the desk. Only then design a stable enclosed stand and validate the print on the actual printer.
